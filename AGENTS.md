# AGENTS.md

## Overview

PyXDF is a Python importer for [XDF](https://github.com/sccn/xdf) (Extensible Data Format) files. It is a small, pure-Python package (requires Python 3.11+, depends only on NumPy) published on PyPI.

## Layout

- `src/pyxdf/pyxdf.py`: the whole library (`load_xdf`, chunk parsing, clock synchronization, dejittering, stream matching)
- `src/pyxdf/cli/`: command line tools (`print_metadata`, `playback_lsl`); `playback_lsl` needs the optional `pylsl` dependency (`playback` extra)
- `src/pyxdf/__version__.py`: generated by hatch-vcs from the git tag, never edit it
- `test/`: pytest tests; some tests use the files from <https://github.com/xdf-modules/example-files> and expect them to be cloned into `example-files/` in the repository root (CI does this, those tests are skipped otherwise)

## Development

The project uses [uv](https://docs.astral.sh/uv/).

```sh
uv sync --all-extras
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

CI runs the format check and the tests on Python 3.11 to 3.15, so avoid syntax or APIs newer than 3.11.

## Conventions

- Format code with `ruff format`; keep `ruff check` clean.
- Add or update tests in `test/` for every behavior change. Changes to loading, synchronization or dejittering should keep output unchanged unless the change is meant to alter it.
- Private helpers are prefixed with `_`; the public API is what `src/pyxdf/__init__.py` exports.
- Every user-visible change needs an entry in `CHANGELOG.md` under the `## [UNRELEASED] - YYYY-MM-DD` header, in the matching `### Added`, `### Changed`, `### Removed` or `### Fixed` section. Follow the existing entry format, which links the PR and credits the author: `- Description ([#123](https://github.com/xdf-modules/pyxdf/pull/123) by [Name](https://github.com/user))`.

## Releasing

1. Open a PR "Prepare vX.Y.Z" that replaces the `[UNRELEASED] - YYYY-MM-DD` changelog header with `[X.Y.Z] - YYYY-MM-DD`, and merge it (squash).
2. Create a GitHub release `vX.Y.Z` targeting `main` with a short prose summary as notes. This creates the tag, and publishing the release triggers `.github/workflows/release.yml`, which builds and publishes to PyPI.
3. Commit "Prepare next dev version" to `main`, which adds a fresh `## [UNRELEASED] - YYYY-MM-DD` header above the new release.
